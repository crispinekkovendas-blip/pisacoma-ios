# Pisacoma iOS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A SwiftUI app with the same screens, content, design and behaviour as the Android app (`E:\pisacoma-android`), built, tested and ad-hoc signed on GitHub Actions.

**Architecture:** XcodeGen project, one app target + unit tests + UI tests. `ContentStore` over the shared `content/` origin. `Route` enum + `NavigationStack`. One SwiftUI view per Android screen, porting the Kotlin file named in each task.

**Tech Stack:** Swift 5.10, SwiftUI, iOS 16, XCTest/XCUITest, lottie-ios 4.x (SPM), XcodeGen, GitHub Actions `macos-15`.

**Spec:** `docs/superpowers/specs/2026-10-13-ios-app-design.md`

## Global Constraints

- No Xcode on this PC: every compile is a CI run. Batch work, read the full error list, fix in one pass.
- Swift files are written with Write/Edit, never bash heredocs.
- The Android source is the reference: port names, copy, tokens and test cases; when Android and the site disagree, the site wins.
- Content origin `https://raw.githubusercontent.com/crispinekkovendas-blip/pisacoma-android/main/content/`; bundled resources copied from the Android repo by `tools/sync-content.mjs`.
- UserDefaults suite `pisacoma`, keys as on Android.
- Nothing in this plan buys, enrols or signs anything with the user's Apple ID.

## Review Focus

1. A universal link with a query (`/biblia/?libro=43&cap=3&v=16`) must open that chapter and highlight the verse (Task 4 `RouteTests.queryStrings`, Task 8 UI).
2. Hymn audio must keep playing with the screen locked (background audio mode + now-playing info; device-only check, documented).
3. First open offline: chooser renders from the bundled manifest; «Descargar todo» ends in the error state (Task 8 UI).
4. Rotating or backgrounding mid-download must not lose progress (downloader lives on the app model, not a view).
5. Lesson markdown with nested quotes and Bible refs renders without crashing (Task 3 ports the Kotlin tests one to one).
